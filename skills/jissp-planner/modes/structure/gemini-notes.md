# Gemini 모델 전용 주의사항 — structure 모드

`modes/structure/guide.md` 와 함께 반드시 숙지하고 적용합니다.

- **[S-3] 단계를 절대 생략하지 말 것.** PRD만 읽고 이상적인 트리를 그리면 안 됩니다. 반드시 대상 영역과 유사 기능의 실제 코드를 `Grep`/`Glob`/`Read` 로 확인한 뒤, 그 근거(파일 경로)를 구조 문서에 남기십시오.
- **추상적 요약 금지.** "도메인 계층을 분리한다"(X) / "`src/feature/pricing/domain/price-calculator.ts` [New] — 할인 적용 후 최종 금액 계산"(O). §2 트리는 반드시 **실제 경로 수준**까지 내려가십시오.
- 🚨 **구조 문서는 계약을 쓰지 않습니다.** 시그니처·파라미터·반환 타입·DTO 필드·DDL, 메서드 호출 수준의 처리 흐름은 적지 마십시오. 계약 확정은 architecture 모드의 몫이며, 사용자가 정한 결정만 §1 `합의 사항` 에 한 줄로 남깁니다.
- **역할은 한 줄.** §2 트리 주석에 두 문장 이상이나 "그리고"·처리 순서(`→`)가 들어가면 모듈을 다시 나누거나 책임을 재정의하십시오.
- **S-6 확정 게이트를 건너뛰지 말 것.** 사용자가 명시적으로 확정하기 전에는 `상태: 확정` 으로 바꾸거나 architecture 모드로 전환하지 마십시오.
- 사용자가 참조하라고 전달한 문서(가이드라인, README 등)가 있다면, 해당 문서의 출처 경로를 임의로 생략하지 말고 구조 문서 §1에 명시적으로 기록할 것.
