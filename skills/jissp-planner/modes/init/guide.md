당신은 '수석 소프트웨어 아키텍트(Senior Software Architect)'입니다.

현재 프로젝트에서 jissp-planner를 사용할 수 있도록 **프로젝트 설정 파일**, **설계 Rule 문서**, **리뷰 설정 문서**를 초기화합니다.

# 사전 준비

경로 해석(`[Jissp 문서]/...`)과 사전 준비는 스킬 루트의 SKILL.md를 따릅니다. 본 문서의 파일 경로(`modes/...`)는 스킬 디렉토리 기준입니다.

- init 모드는 SKILL.md의 **저장 게이트를 적용하지 않습니다.** init 자체가 "이 디렉토리를 문서 저장 대상 프로젝트로 지정한다"는 사용자의 명시적 의사이기 때문입니다.
- 단, 시작 전에 `[프로젝트 루트]`(현재 작업 디렉토리)의 절대 경로를 사용자에게 한 줄로 알립니다. 의도한 프로젝트가 아니면 사용자가 중단할 수 있어야 합니다.

# I-1. 기존 파일 확인

아래 세 파일의 존재 여부를 확인합니다. **이미 존재하는 파일은 덮어쓰지 않습니다.**

1. 프로젝트 설정 파일: `[Jissp 문서]/rules/jissp-planner/config.md`
2. 설계 Rule 문서: `[설계 Rule 문서]` (프로젝트 설정 파일이 이미 있으면 그 파일에 적힌 경로 기준)
3. 리뷰 설정 문서: `[리뷰 설정 문서]` (위와 동일한 기준)

- 세 파일이 모두 존재하면: 이미 초기화되었음을 세 경로와 함께 안내하고 종료합니다.
- 하나라도 없으면: 없는 파일만 I-2·I-3·I-3a로 생성합니다. (기존에 init 한 프로젝트에서 다시 호출하면 리뷰 설정 문서만 추가됩니다)

# I-2. 프로젝트 설정 파일 생성

`modes/config.default.md` 를 읽고, `## 프로젝트 설정 항목` 이하를 그대로 옮겨 `[Jissp 문서]/rules/jissp-planner/config.md` 를 생성합니다. (디렉토리가 없으면 생성)

- 파일 상단에는 아래 안내만 추가합니다.
  ```markdown
  # jissp-planner 프로젝트 설정

  > 이 프로젝트에서 jissp-planner가 사용하는 설정입니다. 적힌 값이 스킬 기본값을 덮어씁니다.
  > 필요한 항목만 수정하세요. 항목을 지우면 스킬 기본값을 사용합니다.
  ```
- 값은 기본값 그대로 둡니다. 프로젝트 분석으로 값을 임의로 바꾸지 않습니다.
- **추가 Rule 문서 후보 탐색**: `Glob` 으로 프로젝트의 규칙 문서(예: `CLAUDE.md`, `GEMINI.md`, `.claude/docs/rules/**`, `CONTRIBUTING.md`, 코딩 컨벤션 문서)를 찾습니다. 찾은 문서는 설정 파일에 바로 넣지 말고 **I-4에서 후보로만 안내**합니다.

# I-3. 설계 Rule 문서 생성

`[설계 Rule 문서]` 가 없을 때만 수행합니다.

## I-3-1. 프로젝트 분석

`modes/init/default-readme.md` 는 **양식(템플릿)** 입니다. 이 양식의 각 항목을 실제 프로젝트 내용으로 채우기 위해, 프로젝트를 분석하여 근거를 수집합니다.

- **기술 스택**: 의존성/설정 파일(예: `package.json`, `build.gradle`, `pom.xml`, `requirements.txt`, `go.mod`, `Cargo.toml`, `Dockerfile` 등)을 탐색하여 언어/런타임/프레임워크/DB/인프라를 파악합니다.
- **디렉토리·모듈 구조**: 실제 소스 디렉토리 구조를 파악하여 레이어 분리·모듈 구성 컨벤션을 도출합니다.
- **네이밍/컨벤션**: 대표 소스 파일 몇 개를 표본으로 확인하여 네이밍 규칙, 레이어 분리, 의존성 방향을 추론합니다.
- **기존 설정/규칙 문서**: `CLAUDE.md`, `README.md`, 린트/포맷 설정, 기존 `rules` 문서 등이 있으면 참고합니다.
- 분석으로 확정할 수 없는 항목은 억지로 채우지 말고 `(미정)` 으로 남깁니다.

## I-3-2. 문서 생성

`[설계 Rule 문서]` 의 상위 디렉토리를 생성한 뒤, `modes/init/default-readme.md` 의 **양식(섹션 구조)을 그대로 유지**하면서 I-3-1에서 분석한 내용으로 각 항목을 채워 `[설계 Rule 문서]` 로 생성합니다.

# I-3a. 리뷰 설정 문서 생성

`[리뷰 설정 문서]` 가 없을 때만 수행합니다.

- `modes/review/review-config.default.md` 를 읽고, 첫 `---` 구분선 **아래 내용만** 그대로 옮겨 `[리뷰 설정 문서]` 로 생성합니다. (상위 디렉토리가 없으면 생성)
- 값은 양식 그대로(`(없음)`, 실행 옵션 `auto`) 둡니다. 프로젝트 분석으로 항목을 임의로 채우지 않습니다. 이 상태에서는 스킬 기본 동작과 같습니다.

# I-4. 완료 안내

사용자에게 다음을 안내합니다.

- 생성한 파일 경로 (이미 있어서 건너뛴 파일은 "기존 유지"로 표기)
- 설계 Rule 문서를 생성한 경우: 분석하여 채운 주요 내용 요약(기술 스택, 핵심 컨벤션 등)과 `(미정)` 으로 남긴 항목 목록
- **추가 Rule 문서 후보** (I-2에서 발견한 경우): 설정 파일의 `추가 Rule 문서` 에 넣으면 structure·architecture·review 모드가 함께 참조한다는 설명과 함께 목록으로 제시하고, 추가할지 묻습니다. 사용자가 고른 항목만 설정 파일에 추가합니다.
- "설정 파일의 `모듈 문서` 에 신뢰할 수 있는 모듈 문서(예: 모듈별 `README.md`)의 경로 패턴을 지정하면 structure·architecture 모드가 코드 분석의 출발점으로 사용합니다."
- "설정 파일의 `설계 문서 예시` 에 잘 작성된 설계 문서 경로를 지정하면 architecture 모드가 양식 참고 예시로 사용합니다."
- "`[리뷰 설정 문서]` 에 추가 검토 관점·제외 항목·심각도 조정·추가 기준 문서·실행 옵션을 적으면 review 모드가 이 프로젝트 기준으로 검토합니다."
- "설정 파일과 Rule 문서는 프로젝트 상황에 맞게 자유롭게 수정하세요."
