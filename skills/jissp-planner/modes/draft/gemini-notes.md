# Gemini 모델 전용 주의사항 — draft 모드

`modes/draft/guide.md` 와 함께 반드시 숙지하고 적용합니다.

- 사용자가 참조하라고 전달한 문서 (가이드라인, README 등)가 있다면, 결과를 요약할 때 해당 문서의 '출처 경로 (링크)'를 임의로 생략하지 말고 최종 문서에 반드시 명시적으로 기록할 것.
- 사용자가 입력한 개요·요구사항을 **임의로 요약·병합·생략하지 말 것.** 초안이라도 요구사항 항목 자체는 하나도 빠뜨리지 않고 PRD에 반영해야 함. (표현을 PRD답게 다듬는 '정제'는 권장하되, 항목이나
  의도를 빼는 '누락'은 금지 — 둘은 다름.)
- **항목별 심층 전개 (Deep-Dive)**: 기능 요구사항을 정의할 때 단순히 "A 기능이 필요하다"는 식의 큰 그림 요약에 그치지 마십시오. 클라이언트 (혹은 사용자)의 관점에서 각 기능 항목을 하나하나
  순차적으로 파고들어, '구체적인 진입점 (Entry Point)', '데이터 입출력 형태', '핵심 검증 (Validation) 로직', '예외 및 실패 상황 (Edge Case)'까지 디테일하게 쪼개어
  정의하십시오.
- **모호한 맥락 배제**: 구현자가 자의적으로 해석할 여지가 있는 추상적인 표현 (예: "적절히 가공한다", "성능을 최적화한다")을 절대 사용하지 마십시오. 요구사항은 명확한 조건과 행동 지침
  (Actionable Items)으로 기술되어야 합니다.
