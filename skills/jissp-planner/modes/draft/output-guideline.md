# Output Format: PRD 문서 초안(draft) 템플릿

- 모든 문서는 Markdown 형식을 따르며 아래 [문서 양식] 구조를 포함해야 합니다.
- SDD(spec-driven-development) 기반으로 작성하세요.
- **초안(draft)이므로 과도하게 상세히 작성하지 말고 핵심만 간결하게 작성**합니다.
  - 단, **'간결하게'는 표현을 부풀리지 말라는 뜻일 뿐, 사용자가 전달한 개요·요구사항을 생략·누락해도 된다는 뜻이 절대 아닙니다.** 입력받은 모든 요구사항은 하나도 빠짐없이 문서에 반영합니다.
- 입력받은 개요와 요구사항으로 채울 수 없는 항목은 억지로 채우지 말고, `(미정)` 또는 추천안 제시 수준으로 간결히 남깁니다.

## 저장 위치

- 저장 경로: `[Jissp 문서]/[PRD 문서]/`
  - `[Jissp 문서]`와 `[PRD 문서]`는 SKILL.md 사전 준비에서 확정한 설정 값으로 해석하며, 디렉토리명을 추측하거나 임의로 만들지 않습니다.
  - 디렉토리가 없으면 생성합니다. (생성 전 SKILL.md의 저장 게이트를 따릅니다.)
- 사용자가 저장 경로를 명시한 경우에는 지정된 경로를 우선시합니다.
- 태스크 모드(`--task`)면 위 규칙 대신 SKILL.md "태스크 모드"의 저장 위치·파일명(`[태스크 디렉토리]/prd.md`)을 따릅니다.

## 파일명 규칙

- 파일명: `[파일명 규칙]` 을 따르며, 문서 유형은 `prd` 입니다.
  - `[feature]` 는 개요·요구사항의 핵심 기능명에서 도출합니다.
  - 예) `20260923_143205_export-csv-prd.md` (기본 파일명 규칙 기준)

## 문서 양식
---
1. **프로젝트 개요**: 목적, 대상 독자, 핵심 가치 제안. (사용자가 입력한 '개요' 기반)
2. **요구사항 명세**: 구현·작업 순서 기준의 우선순위별 기능적 요구사항(P0, P1, P2). (사용자가 입력한 '요구사항'을 분석하여 선행/후행 등 작업 순서를 도출해 우선순위를 매긴다. 사용자가 정한 선호도가 아니라 '무엇을 먼저 만들어야 하는가' 기준.)
3. **시스템 아키텍처**: 전체 구조도, 기술 스택 선정 이유.
4. **데이터 모델**: 핵심 데이터 엔티티 정의.
5. **API/인터페이스 설계**: 주요 API 엔드포인트 또는 인터페이스 정의.
6. **사용자 흐름(User Flow)**: 주요 시나리오별 단계별 흐름.
7. **비기능적 요구사항**: 보안, 성능, 확장성 고려사항.
---

# Flow 도식화 첨부 (필요 시)

- 요구사항에 명확한 흐름(User Flow, 처리 프로세스 등)이 있어 도식화가 이해에 도움이 되는 경우, `/flow-diagram` 스킬로 도식을 생성합니다.
- 생성된 도식은 위 문서의 **6. 사용자 흐름(User Flow)** 항목에 첨부하거나 별도 절로 포함합니다.
