# README 작성 규칙

`jissp-module-analysis`가 작성하는 모듈 README의 섹션 구성·작성 규칙·업데이트 모드 규칙입니다.

## 1. 섹션 구성

아래 순서를 기본으로 하며, 대상 모듈에 해당 내용이 없으면 섹션을 **생략**합니다. (빈 섹션이나 "없음"만 적힌 섹션을 만들지 않습니다.)

| # | 섹션 | 내용 | 필수 |
|---|------|------|------|
| 1 | `# [모듈명]` + 한두 문장 소개 | 이 모듈이 무엇을 책임지는지 | ✅ |
| 2 | `## 디렉토리 구조` | 코드블록 트리 + 각 항목 한 줄 설명 | ✅ |
| 3 | `## 주요 구성요소` | 파일/하위 디렉토리별 책임 표 | ✅ |
| 4 | `## 동작 흐름` | `flow-diagram` 산출 ASCII 도식 (전체 구조 → 동작별 흐름 → 한 줄 요약) | 흐름이 있을 때 |
| 5 | `## 공개 인터페이스` | 외부에서 사용하는 export·API·엔드포인트·이벤트 표 (이름 / 설명 / 위치) | 있을 때 |
| 6 | `## 의존 관계` | 의존 관계 ASCII 도식 + 의존 대상 목록 + 사용처 표 (1.1절) | ✅ |
| 7 | `## 설정` | 환경 변수·설정 키와 용도 | 있을 때 |
| 8 | `## 테스트` | 테스트 위치와 실행 명령 | 있을 때 |
| 9 | `## 주의 사항` | 코드에서 확인된 제약·함정·부수효과 (⚠ 표기) | 있을 때 |

### 1.1 의존 관계 섹션 규칙

모듈 **경계 바깥**과의 관계만 다룹니다. 모듈 내부 구성요소 간 흐름은 "동작 흐름" 섹션의 몫이므로 여기서 그리지 않습니다.

구성 순서: **도식 → 의존 대상 → 사용처**

1. **의존 관계 도식** (ASCII 코드블록)
   - 좌 → 중앙 → 우 3분할: `사용처 모듈` → `[대상 모듈 박스]` → `의존 대상`
   - 사용처 → 대상 화살표에는 그 모듈이 사용하는 대표 공개 인터페이스를 표기합니다. (여러 개면 대표 1개 + `외 N`)
   - 의존 대상은 종류를 접두어로 구분합니다: 내부 모듈은 이름 그대로, 외부 라이브러리는 `(lib)`, 인프라는 `[DB]`·`[Queue]`·`[API]` 등.
   - 한쪽이 많아(대략 6개 초과) 도식이 길어지면 주요 항목만 그리고 `… 외 N개 (아래 표 참조)`로 줄입니다. 전체 목록은 표에 둡니다.
   - 정렬은 `flow-diagram/references/diagram-format.md`의 정렬 규칙을 따릅니다. 박스 안에는 가급적 ASCII 식별자만 넣습니다.
2. **의존 대상** — 목록 또는 표 (대상 / 종류 / 사용하는 구성요소)
3. **사용처** — 표 (사용 모듈 / 대표 파일 / 사용하는 인터페이스)
   - **모듈 단위로 묶고** 대표 파일은 1~2개만 적습니다. 파일을 전부 나열하지 않습니다.
   - 테스트 코드는 사용처에 넣지 않습니다.
   - grep으로 확정하기 어려운 사용처(이벤트명·DI 토큰·HTTP 경로 등 문자열 기반 호출)는 `확인 필요`로 표시합니다.
   - 사용처가 없으면 표 대신 한 줄로 그 사실을 적습니다. (예: `레포 내 사용처 없음 — 애플리케이션 진입점`)

### 예시 골격

````markdown
# credit

크레딧 충전·소모·롤백을 담당하는 모듈입니다. 모든 크레딧 변동은 원장(ledger)에 기록됩니다.

## 디렉토리 구조

```
credit/
├── credit.service.ts      # 충전·소모·롤백 진입점
├── credit.repository.ts   # 원장 조회·기록
└── dto/                   # 요청·응답 DTO
```

## 주요 구성요소

| 구성요소 | 책임 |
|----------|------|
| `credit.service.ts` | 크레딧 변동 비즈니스 로직, 트랜잭션 경계 |
| `credit.repository.ts` | 원장 테이블 접근 |

## 동작 흐름

```
(flow-diagram 도식)
```

## 의존 관계

```
     사용처                          대상 모듈                      의존 대상
 ─────────────                   ┌──────────────┐               ─────────────
  order ── chargeCredit ───────► │              │ ────────────► payment
  admin ── getBalance ─────────► │    credit    │ ────────────► (lib) typeorm
                                 │              │ ────────────► [DB] credit_ledger
                                 └──────────────┘
```

### 의존 대상

| 대상 | 종류 | 사용하는 구성요소 |
|------|------|-------------------|
| `payment` | 내부 모듈 | `credit.service.ts` |
| `typeorm` | 외부 라이브러리 | `credit.repository.ts` |
| `credit_ledger` | MySQL 테이블 | `credit.repository.ts` |

### 사용처

| 사용 모듈 | 대표 파일 | 사용하는 인터페이스 |
|-----------|-----------|---------------------|
| `order` | `order.service.ts` | `chargeCredit` |
| `admin` | `admin-credit.controller.ts` | `getBalance` |
````

## 2. 작성 규칙

- 경로는 **대상 디렉토리 기준 상대 경로**로 씁니다. (절대 경로·사용자 홈 경로를 쓰지 않습니다.)
- 식별자·파일명은 백틱으로 감쌉니다.
- 구현 세부(라인 단위 로직)를 옮겨 적지 않습니다. README는 "무엇을·왜·어디서"를 설명하고, "어떻게"는 코드와 도식이 담당합니다.
- mermaid 등 렌더링이 필요한 형식은 쓰지 않습니다. 도식은 코드블록 ASCII만 사용합니다.
- 코드에서 확인하지 못한 내용은 쓰지 않거나 `확인 필요`로 표시합니다.
- 코드를 따라 갱신이 필요한 수치(파일 개수, 라인 수 등)는 넣지 않습니다.

## 3. 업데이트 모드

기존 README를 **존중하며 보강**하는 것이 원칙입니다. 전체를 다시 쓰지 않고 Edit로 필요한 부분만 고칩니다.

| 기존 README 상태 | 처리 |
|------------------|------|
| 1절 섹션과 대응되는 섹션이 있고 내용이 코드와 일치 | 유지 |
| 대응 섹션이 있으나 코드와 다름 (삭제된 파일, 바뀐 인터페이스 등) | 코드 기준으로 수정 |
| 대응 섹션이 없음 | 1절 순서에 맞는 위치에 추가 |
| 1절에 없는 섹션 (사용 예시, 히스토리, 담당자, 링크 등 사람이 쓴 내용) | **그대로 유지** — 삭제·재작성하지 않음 |
| 기존 동작 흐름 도식이 있음 | 새 도식으로 교체하되, 도식 외 설명 문단은 코드와 일치하면 유지 |
| 기존 의존 관계 섹션이 목록뿐임 | 도식·사용처 표를 1.1절 구성으로 추가하고, 기존 목록은 코드와 일치하면 표로 흡수, 다르면 코드 기준으로 수정 |

- 기존 README의 섹션 제목 표기·언어·어투를 따릅니다. (예: 기존이 `## Structure`면 `## 디렉토리 구조`로 바꾸지 않습니다.)
- 코드와 달라서 **기존 서술을 수정·삭제한 경우** 결과 보고에 그 내역을 반드시 포함합니다.
