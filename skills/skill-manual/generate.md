# generate — 매뉴얼 생성·최신화

지정된 스킬의 사용 방법을 읽어 `manuals/[스킬명].md` 를 생성하거나 최신화합니다.

## 1. 대상 스킬 확정

- 인자가 없으면 어떤 스킬의 매뉴얼을 만들지 텍스트로 묻습니다.
- 매뉴얼 파일명은 **스킬 이름 그대로** 사용합니다. 스킬명을 축약하거나 별칭을 만들지 않습니다.
- 원본 스킬 디렉토리를 아래 순서로 찾고, 처음 찾은 곳을 `[원본]` 으로 사용합니다.
  1. `~/jissp-agent-kit/skills/[스킬명]` (본문: `SKILL.claude.md`)
  2. `~/.claude/skills/[스킬명]` (본문: `SKILL.md`)
  3. `~/.gemini/antigravity-cli/skills/[스킬명]` (본문: `SKILL.md`)
- 어디에도 없으면 추측하지 말고, 비슷한 이름의 스킬 디렉토리를 후보로 보여주고 확인받습니다.

## 2. 사용 방법 수집

- `[원본]` 의 본문을 읽고 **사용자가 입력하는 것**만 추립니다: 명령·alias·모드, 인자 형식과 생략 시 동작, 옵션(`--xxx`), 설정 파일 위치, 권장 흐름.
- 본문만으로 인자 형식이 불분명할 때만 본문이 가리키는 하위 문서(라우팅 표의 참조 문서 등)를 **해당 부분만** 읽습니다. 하위 문서를 일괄로 읽지 않습니다.
- 내부 절차·판단 규칙·출력 양식 같은 동작 상세는 매뉴얼에 넣지 않습니다.

## 3. 매뉴얼 작성

기존 매뉴얼이 있으면 먼저 읽고, 섹션 구성을 유지한 채 바뀐 부분만 반영합니다.

~~~markdown
---
skill: [스킬명]
source: [원본 디렉토리 경로 (`~/` 표기, 예: ~/jissp-agent-kit/skills/[스킬명])]
generated_at: [date +"%Y-%m-%d %H:%M:%S"]
---

### [명령 그룹명]   ← 그룹이 하나면 "### 명령어"

| 용도 | 명령어 |
|---|---|
| [용도] | `/[스킬명] [명령] [인자]` — [생략 시 동작·옵션 등 한 줄 보충] |

- [권장 흐름·명령 간 관계 등 꼭 필요한 보충만]

### 인자 참고

- `[인자]`: [허용 형식] · [생략 시 동작]

### 설정 참고   ← 설정 파일이 있는 스킬만

- [설정 파일 경로] — [무엇을 지정하는지]

### 예시

```
/[스킬명] [실제로 쓸 법한 호출 3~6개]
```
~~~

- **분량**: 4KB 이내를 목표로 합니다. 조회 때마다 그대로 출력되는 문서입니다.
- 명령어 표기는 실제 호출 형태(`/스킬명 ...`)로 적고, 본문에 없는 명령·옵션을 지어내지 않습니다.

## 4. 저장·보고

- `~/jissp-agent-kit/skills/skill-manual/manuals/[스킬명].md` 에 저장합니다. (파일 mtime 이 최신 여부 판단 기준이 되므로 반드시 다시 저장합니다)
- **새로 만든 매뉴얼이면** `SKILL.claude.md`·`SKILL.gemini.md` 의 「매뉴얼 목록」 표에 `| [스킬명] | [용도 한 줄] |` 행을 스킬명 오름차순 위치에 추가합니다. 두 파일을 같은 내용으로 맞춥니다. (최신화일 때는 용도가 바뀐 경우만 고칩니다)
- 보고: 생성/최신화 여부, 저장 경로, (최신화인 경우) 추가·변경·삭제된 명령을 개조식으로 짧게 정리합니다. 매뉴얼 본문 전체를 다시 출력하지 않습니다.
