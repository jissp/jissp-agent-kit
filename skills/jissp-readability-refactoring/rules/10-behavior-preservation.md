# 4. 동작 보존

- 외부에서 관찰 가능한 동작(입출력, 예외 흐름, 부수효과 순서)을 한 톨도 바꾸지 않는다.
  - 재시도 판정·예외 재발생(`throw error`)·데코레이터 설정·DI 토큰 등 런타임 제어 흐름을 건드리지 않는다
  - 로그 메시지의 최종 문구도 관찰 가능한 동작이다. 템플릿 문자열을 정리하더라도 출력 텍스트는 같아야 한다
- 명백한 버그로 보이는 부분도 수정하지 않는다. "범위 외 관찰"로 보고만 한다.

## 접근 시점 이동

구조 분해(`rules/03`)·단계 분리(`rules/02`)·임시 변수 추출로 값을 읽는 시점이 앞당겨질 때는 아래를 모두 만족해야 한다.

- **try/catch 경계를 넘기지 않는다** — try 안의 접근을 try 밖으로 올리면, 접근 중 발생한 예외가 catch(재시도 판정·실패 처리)를 건너뛴다. try 밖으로 올리는 것은 해당 경로가 타입상 non-nullable인 일반 프로퍼티라 접근 자체가 예외를 던질 수 없을 때만 허용한다. 그 외에는 try 블록 안 시작 지점에 둔다
- **분해 이후 원본이 바뀌지 않는다** — 분해 지점과 사용 지점 사이에 원본 객체의 재할당·변경(mutation)이 있으면 분해하지 않는다
- **호출 횟수를 줄이는 것은 순수 조회일 때만** — `payment.getData()` 같은 메서드·getter 반복 호출을 한 번으로 합치는 것은, 그 호출에 부수효과가 없고 매번 같은 값을 돌려줄 때만 허용한다
