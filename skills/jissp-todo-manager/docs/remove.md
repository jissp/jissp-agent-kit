# TODO 삭제 절차 (rm)

> 선행: [structure.md](structure.md)의 저장 구조·탐색 방법을 따릅니다.

사용법: `/jissp-todo-manager rm [todo명]`

더 이상 처리하지 않기로 한 TODO(취소·중복·오등록)를 저장소에서 제거합니다.

## 절차

1. **대상 특정**: [structure.md](structure.md)의 탐색 순서(활성 → assigned)로 TODO를 찾습니다. 모호하면 후보 목록을 제시하고 선택받습니다.
2. **승인 [필수 게이트]**: 삭제 대상의 **디렉토리 절대 경로 · `name` · `status` · 제목 · 포함된 파일 목록**을 제시하고 사용자 승인을 받습니다. **승인 없이 삭제하지 않습니다.**
3. **삭제**: 승인 후 해당 TODO 디렉토리를 삭제합니다.
4. **결과 보고**: 삭제된 경로를 알립니다.

## 주의

- **프로젝트로 할당해 처리하려는 경우에는 `rm`이 아니라 `assign`을 사용합니다.** `assign`은 태스크로 이관한 뒤 TODO를 `assigned/`로 옮기므로 이력이 남습니다. `rm`은 이력 없이 사라집니다.
- 이미 `assigned` 상태인 TODO를 삭제하려 하면, **이미 생성된 프로젝트 태스크는 함께 삭제되지 않는다**는 점을 알리고 `assigned_task` 경로를 제시한 뒤 승인받습니다.
- 삭제 대상이 TODO 루트(`todos/`) 자체이거나 `assigned/` 디렉토리 전체인 요청은 수행하지 않습니다. 개별 TODO 디렉토리만 삭제합니다.
