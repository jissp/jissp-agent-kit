# [처리 절차] 업무 요청 — 요구사항 정리

업무 요청(신규 기능·개선·유지보수 등)으로 분류된 건은 아래 절차를 순서대로 진행합니다.
이 절차는 **원문이 요청한 것을 정리하는 데까지**입니다. 코드를 보지 않으며, 현행 동작·영향 범위·구현 방향은 `jissp-code-analyzer`의 몫입니다.

## 1. 요청 내용 확인
- 원문에서 요구사항을 항목 단위로 분해합니다. **명시된 것**과 **암묵적으로 가정된 것**을 구분합니다.

## 2. 참조 문서 확인
링크된 Figma/Notion/GitHub 등을 실제로 열어 확인합니다.
- 문서에만 있고 원문엔 없는 요구사항 → `추가 발견 사항`으로 표기
- 문서와 원문이 충돌 → `충돌`로 표기하고 `확인 필요 사항`에 올립니다
- 접근 불가 → `확인 불가`로 명시한 뒤 진행합니다. (명시 없이 조용히 넘어가지 않습니다)

## 3. 범위·기대 결과 정리
원문과 참조 문서에 **근거가 있는 것만** 적습니다.
- `In Scope` : 원문이 요청한 것
- `Out of Scope` : 원문에서 이번에 하지 않는다고 했거나, 요청과 구분해야 할 것 (근거 포함)
- `의존성` : 원문에 언급된 선행 작업, 타 팀 협조, 외부 결정 사항
- `기대 결과` : 요청이 충족되었다고 볼 수 있는 조건 (원문 기준. 원문에 없으면 `확인 필요 사항`으로)

## 4. 요구사항 문서 본문 가공
이 스킬 디렉토리의 `templates/work-request-requirements.md` 양식으로 가공합니다. (SKILL.md의 [반환 규칙] 참고)
- **파일로 저장하지 않습니다.** 저장은 호출자의 몫입니다.

## 5. 요약 작성
- 본문과 함께 반환할 요약에는 요구사항 개수 / In Scope 핵심 / 주요 확인 필요 사항만 간결히 담습니다.
- `확인 필요 사항`은 요약에 담기만 하고, 이 단계에서 사용자에게 따로 묻지 않습니다. 답을 받는 것은 호출자의 몫입니다.

## 6. 절차 종료 후
[반환 규칙]의 4개 항목(문서 유형·핵심 키워드·문서 본문·요약)을 갖춘 뒤 SKILL.md [종료 처리]에 따라 분기합니다.
- 다른 스킬이 호출한 경우: 여기서 응답을 끝내지 말고 **호출한 스킬의 다음 단계로 복귀**합니다.
- 사용자가 직접 호출한 경우: 본문 전문과 요약을 채팅에 출력하고 종료합니다.
