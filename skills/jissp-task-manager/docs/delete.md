# 삭제 절차 (태스크 · feature)

> 선행: [structure.md](structure.md)의 저장 구조를 따릅니다.
> ⚠️ 삭제는 되돌리기 어려운 작업입니다. 반드시 사용자 승인 후 수행합니다.

## 태스크 삭제 (`rm [feature] [task]`)

### 1. 대상 태스크 특정

- 사용자가 지정한 태스크를 structure.md의 탐색 방법으로 찾습니다.
- 지정이 모호하면 후보 목록을 보여주고 선택받습니다.

### 2. 삭제 승인 (필수)

- 삭제 전 반드시 아래 정보를 사용자에게 제시하고 **명시적 승인**을 받습니다.
  - feature, 태스크 디렉토리 경로
  - `name`, `status`, 등록일
  - 디렉토리에 포함된 파일 목록
- 승인 없이 절대 삭제하지 않습니다.
- `processing` 상태의 태스크라면 처리 중임을 경고하고 재확인합니다.
- feature에서 다른 태스크 README의 "선행 태스크" 절이 이 태스크를 가리키면, 해당 태스크 목록도 함께 경고합니다.

### 3. 삭제 수행

- 승인받은 태스크 디렉토리를 통째로 삭제합니다. (`rm -rf [태스크 디렉토리]`)
- feature면 feature README "태스크 목록" 표에서 행을 제거하고 "이력"에 `태스크 삭제: [NN]_[task-slug]` 를 남깁니다. **번호는 재정렬하지 않습니다.**
- 완전 삭제가 아니라 "나중에 할 수도 있음"이라면 삭제 대신 `backlog`/`holding` 전이([status.md](status.md))를 대안으로 제안합니다.

### 4. 결과 보고

- 삭제된 태스크와 경로를 사용자에게 보고합니다.

## feature 삭제 (`feature rm [slug]`)

- `maintenance` 는 삭제할 수 없습니다.
- 삭제 전 feature 경로, 태스크 목록(번호·name·status), `docs/` 파일 목록을 제시하고 **명시적 승인**을 받습니다.
  - `processing` 태스크가 있으면 경고하고 재확인합니다.
  - 삭제 대신 feature 완료(`_completed/` 로 보관)나 `holding` 을 대안으로 먼저 제안합니다.
- 승인 후 `rm -rf features/[slug]` (또는 `features/_completed/[slug]`) 로 삭제하고 결과를 보고합니다.
