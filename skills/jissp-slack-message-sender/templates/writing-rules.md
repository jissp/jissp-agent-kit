# [작성 규칙] 슬랙 메시지

`jissp-slack-message-sender`가 초안을 작성·수정할 때 따르는 규칙입니다.
**공통 규칙**은 항상 적용하고, **독자별 규칙**은 입력의 `독자`에 맞는 것 하나만 적용합니다.

## 공통 규칙

### 슬랙 문법
`slack_send_message`는 **표준 마크다운**을 받아 슬랙 형식으로 바꿉니다. 슬랙 고유 문법(`*굵게*`)으로 쓰면 기울임으로 보이므로 쓰지 않습니다.
- 굵게: `**텍스트**`
- 목록: `•` 또는 `-`
- 링크: `<URL|표시 텍스트>` 대신 표준 마크다운 `[표시 텍스트](URL)`
- `#` 헤딩은 쓰지 않습니다. 제목은 첫 줄을 `**굵게**`로 씁니다.
- 한 메시지는 5,000자를 넘기지 않습니다.

### 내용
- **결론 먼저**: 첫 항목에서 핵심 결론을 바로 알 수 있게 합니다.
- **근거 없는 단정 금지**: 근거에서 확인된 내용만 씁니다. 추정이면 "~로 보입니다", 미확인이면 "확인되지 않았습니다"로 씁니다.
- **해당 없는 항목은 생략**합니다. 빈 항목이나 "없음"을 남기지 않습니다.
- **문체**: 존댓말 문장형(`~입니다`, `~합니다`).

## 독자별 규칙

### 비개발자 (기본값 — 제품팀·CS팀·운영팀)
- **코드 용어 금지**: 파일 경로·함수명·변수명·API 경로·에러 코드·테이블명을 쓰지 않습니다.
  - 기술 용어를 피할 수 없으면 괄호로 쉽게 풀어 씁니다. 예) 캐시(임시로 저장해 둔 데이터)
- **사용자 관점으로 서술**: 시스템 내부 동작이 아니라 "사용자가 무엇을 보고, 무엇을 했을 때, 어떻게 되는지"로 씁니다.
  - ❌ `OrderService`에서 null 체크가 누락되어 예외 발생
  - ⭕ 배송지를 입력하지 않고 주문하면 주문 버튼이 반응하지 않습니다
- **분량**: 항목당 1~2문장, 전체 5~10줄. 길어지면 덜 중요한 내용부터 뺍니다.
- 표·코드블록은 쓰지 않습니다.

### 개발자
- 파일 경로·함수명·API 경로를 써도 됩니다. 식별자는 `` `코드` `` 로 감쌉니다.
- 근거 코드 위치는 `경로:줄` 형식으로 씁니다.
- **분량**: 전체 15줄 이내. 상세 내용은 문서 경로로 대신합니다.
- 코드블록은 짧은 예시(5줄 이내)에만 씁니다.
