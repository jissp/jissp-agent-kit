# ASCII 플로우 도식 표기 규칙

이 문서는 `flow-diagram` 스킬이 생성하는 도식의 **표준 표기법**을 정의한다.
목표: mermaid 없이 markdown 코드블록 안에서 바로 읽히는, 정렬이 깔끔한 텍스트 도식.

## 1. 사용 문자 세트

| 용도 | 문자 |
|------|------|
| 박스 테두리 | `┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼ ─ │` |
| 수직 흐름 | `│` (세로선), `▼` (아래 방향 진행) |
| 수평/분기 화살표 | `──►` , `├──` , `└──` , `─►` |
| 연결 가지 | `├─` , `└─` (하위 항목 나열) |
| 단계 번호 | `[1] [2] [3] ...` |
| 강조 기호 | `⚠`(주의/리스크), `✗`(예외·실패·차단), `✅`(보장됨), `★`(핵심 포인트) |

> 기호는 의미를 일관되게 유지한다. 원본 분석 문서가 특정 기호(예: ⚠)를 쓰면 그 의미를 그대로 계승한다.

## 2. 도식 패턴별 템플릿

### 2.1 전체 구조 관계도 (섹션 0)

진입 경로(좌) → 핵심 모듈/컴포넌트(중앙 박스) → 데이터/상태 보관처(우) 의 3분할 배치를 권장.

```
   진입 경로                  ┌──────────── 핵심 모듈 ────────────┐        보관처
 ───────────                 │                                   │      ───────
  [컨트롤러] ───────┐        │   application / 핸들러 묶음        │     ┌─────────┐
  [이벤트]   ───────┼──────► │   ┌──────┬──────┬──────┐          │     │  상태    │
  [외부서비스]──────┘        │   │ 동작A│ 동작B│ 동작C│          │     │  저장소  │
                             │   └──────┴──────┴──────┘          │     └────┬────┘
                             │             │ 기록               ─┼──────────┘
                             └─────────────┼─────────────────────┘
                                           ▼
                                 공통 불변식 / 트랜잭션 경계
```

### 2.2 순차 흐름 + 분기 (동작별 상세, 섹션 2~N)

단계 번호와 세로 진행을 기본으로, 조건 분기는 `├──`/`└──`로 갈래를 표현.

```
  진입점 설명
       │
  [1] 첫 단계
       │
  [2] 조건 검사
       │   조건 X 인가 ?
       │        └── YES ──► ✗ 예외/조기 종료 (사유)
       ▼
  [3] 처리 단계 ── 부연 설명
       │
       ▼
     완료 / 반환값
```

분기가 양 갈래로 갈라질 때:

```
  판단 ?
     │
     ├── true ──►  경로 A 결과
     │
     └── false ─►  경로 B 결과
                       │
                       ▼
                   이어지는 단계
```

### 2.3 변형 비교 표 (한 동작에 여러 구현/변형)

```
 ┌──────────────┬──────────────┬──────────────┬──────────────┐
 │    구분      │     키       │   처리 방식  │   멱등성     │
 ├──────────────┼──────────────┼──────────────┼──────────────┤
 │ 변형 A       │ ...          │ ...          │ ✅           │
 ├──────────────┼──────────────┼──────────────┼──────────────┤
 │ 변형 B       │ ...          │ ...          │ ✗ 없음       │
 └──────────────┴──────────────┴──────────────┴──────────────┘
```

> 일반 markdown 표(`| ... |`)로도 충분하면 그것을 써도 된다. ASCII 박스 표는 코드블록 안에서 도식과 시각적 통일성이 필요할 때 사용.

### 2.4 상태 전이

```
   [동작 A]                      [동작 B]
   ─────────                     ─────────
   상태 = success    ──────►     상태 = rollback
   id 반환                       원본 id 참조
       │                              ▲
       └──────────────────────────────┘
```

### 2.5 한 줄 요약 (마지막 섹션)

```
동작A: 진입 → 전처리 → 검증 → 핵심처리 → 결과
동작B: 진입 → 전처리 → 검증 → 핵심처리 → 결과
공통: (모든 동작이 공유하는 불변식 한 줄)
```

## 3. 정렬 규칙 (중요)

ASCII 도식의 품질은 **정렬**이 좌우한다. 다음을 반드시 지킨다.

- **한글은 전각(2칸 폭)**이다. 박스 안에 한글이 들어가면 같은 글자 수라도 영문보다 폭이 넓어 테두리(`│`, `┐`)가 어긋난다.
  → 박스 폭을 정할 때 한글 1자 = 영문 2자로 계산하여 여백을 맞춘다.
  → 어긋남이 불가피하면, 박스 안 라벨을 **짧은 영문/약어**로 바꾸거나 박스를 키워 정렬한다.
- 세로 흐름의 `│`와 `▼`는 **같은 열(column)** 에 오도록 앞쪽 공백 수를 일정하게 유지한다.
- 분기 `├──`/`└──`는 부모 `│`보다 들여쓰고, 같은 레벨 갈래끼리 들여쓰기를 통일한다.
- 작성 후 반드시 **한 번 더 눈으로 열을 맞춰 검수**한다. (생성 직후 정렬이 틀어지는 경우가 잦음)

## 4. 금지/주의

- mermaid / PlantUML / graphviz 등 렌더링 필요 형식 금지. 오직 코드블록 내 텍스트.
- 도식 안에 장문 설명을 넣지 않는다. 부연은 코드블록 밖 본문이나 `──` 뒤 짧은 주석으로.
- 과도한 박스 남발 금지 — 단순 순차 흐름은 `│`/`▼`만으로 충분하다. 박스는 묶음/경계를 보여줄 때만.
- 원본 문서/코드에 없는 흐름을 임의로 추가하지 않는다.
